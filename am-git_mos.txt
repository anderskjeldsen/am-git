am-git - a native git client for MorphOS
========================================

am-git talks to git servers directly over the network. It can clone,
commit, push, fetch and pull against HTTPS git remotes such as GitHub -
no separate git program needed. Local commands (log, status, branch,
checkout, merge, rebase, diff, ...) work offline.

TLS is linked in statically - nothing extra to install.

ssh remotes are not supported in this MorphOS build yet; use an
https:// remote instead (GitHub: use a personal access token as the
password).


-------------------------------------------------------------------------
1. SETUP
-------------------------------------------------------------------------

Tell am-git who you are (used when you commit):

  setenv AM_GIT_USER_NAME  "Your Name"
  setenv AM_GIT_USER_EMAIL "you@example.com"

To push, or to clone a private repo, set your login and token:

  setenv AM_GIT_USERNAME "your-login"
  setenv AM_GIT_PASSWORD "ghp_yourAccessToken"

GitHub no longer accepts plain passwords - use a personal access token
in AM_GIT_PASSWORD.

AM_GIT_USERNAME/PASSWORD is a single login. To keep DIFFERENT logins for
different servers, put them in AM_GIT_NETRC instead - the variable holds
the whole credentials list (one "machine" line per host):

  machine github.com login alice password ghp_alicetoken
  machine gitlab.com  login bob   password glpat_bobtoken
  machine 172.16.0.132 login anders password lansecret

am-git picks the line matching the host it connects to. To trust two
logins on the SAME host, name the one you want in the URL, e.g.
https://bob@github.com/... . AM_GIT_USERNAME/PASSWORD still work as a
fallback when no line matches. (Credentials in a clone URL like
https://user:token@host/... always win.)

`setenv` stores each variable in ENV:, which lasts until reboot. To make
them permanent, copy them from ENV: to ENVARC: (ENVARC: is restored into
ENV: at every boot):

  copy ENV:AM_GIT_#? ENVARC:

Give am-git enough stack - set it to at least 100000 bytes before you
run it, or it may crash on larger repositories:

  stack 100000

Put this in your shell startup (or S:User-Startup) so you don't have to
type it every time.


-------------------------------------------------------------------------
2. A TYPICAL SESSION
-------------------------------------------------------------------------

  am-git clone https://github.com/youruser/myrepo.git
  cd myrepo

  am-git log -n 5                 ; recent history
  am-git branch                   ; list branches
  am-git status                   ; what has changed

  am-git pull                     ; get the latest from the server

  ; edit a file, then:
  am-git add NOTES.txt            ; stage it
  am-git status                   ; confirm it is staged
  am-git commit -m "Add NOTES.txt"

  am-git push                     ; send it back to the server


-------------------------------------------------------------------------
3. COMMANDS
-------------------------------------------------------------------------

Run `am-git help` for the full list. The everyday ones:

clone <url> [<dir>]
    Download a repository and check it out. <dir> defaults to the repo
    name.
      am-git clone https://github.com/youruser/myrepo.git
      am-git clone https://github.com/youruser/myrepo.git work

fetch [<name>]
    Get new commits from the server without changing your files.
      am-git fetch

pull [<url>] [<branch>]
    Fetch, then update your branch: fast-forward when possible,
    otherwise a 3-way merge (conflicts leave markers to resolve).
      am-git pull

push [<url>] [<branch>]
    Send your commits to the server.
      am-git push
      am-git push origin main

add <path>...
    Stage files for the next commit. Use "." to add everything.
      am-git add NOTES.txt
      am-git add .

rm [--cached] <path>...
    Stop tracking a file. Without --cached the file is also deleted;
    with --cached it stays on disk.
      am-git rm oldfile.txt
      am-git rm --cached secret.key

status
    Show what is staged, what is changed but unstaged, and what is
    untracked.
      am-git status

log [-n <N>]
    Show commit history. -n limits how many are shown.
      am-git log
      am-git log -n 10

branch [<name> | -d <name>]
    No argument lists branches. A name creates one; -d deletes one.
      am-git branch
      am-git branch feature-x
      am-git branch -d feature-x

checkout <branch>
    Switch to another branch. Refuses if you have uncommitted changes
    that would be overwritten - commit or reset them first.
      am-git checkout main

merge <branch>
    Merge another branch into the current one. Fast-forwards when it
    can; otherwise makes a merge commit, or stops with conflict
    markers in the files for you to resolve (then add + commit).
      am-git merge feature-x

tag [<name> [<commit>]] | -d <name>
    No argument lists tags. A name creates a lightweight tag; -d
    deletes one.
      am-git tag v1.0

diff [--staged] [<a> [<b>]]
    Show changes as a unified diff (working tree, index or between
    commits).
      am-git diff

commit -m <msg>
    Record the staged files as a new commit.
      am-git commit -m "Fix the parser crash"

head
    Show which branch or commit you are currently on.
      am-git head

whoami
    Show the name and email your commits will use.
      am-git whoami


-------------------------------------------------------------------------
4. GOOD TO KNOW
-------------------------------------------------------------------------

- pull fast-forwards when it can, and otherwise falls back to a real
  3-way merge. Conflicts are written to the files with the usual
  <<<<<<< / ======= / >>>>>>> markers; resolve, add and commit.
- merge, rebase, cherry-pick and revert all work locally, including
  --continue / --abort where a conflict stops the run.
- Supported remotes: https:// and http://. ssh and git:// URLs are
  not supported in this MorphOS build.
- Your name, email, login and token come from the environment
  variables shown in section 1.
